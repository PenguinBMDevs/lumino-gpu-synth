# Session 2026-08-10：lumino-gpu-synth 首个可运行版本 + 对齐验证

## 任务
从零搭建 GPU 实时 MIDI 音频渲染 crate（wgpu27 compute + lumino-midly + xsynth-soundfonts），
用 right-example.mid + test.sf2 渲染并与 right-example.wav 对比（目标 99%+）。

## 关键决策
- **依赖**：crates.io（wgpu 27.0.1 / lumino-midly 0.6.2 / xsynth-soundfonts 0.4.0 / cpal 0.18）。
  注意：crates.io 的 xsynth-soundfonts 0.3.4 是旧 API（无 note_params）；0.4.0 才是与本地
  xsynth-normal（0.3.4 修改版）一致的新架构。
- **参考音频溯源**："64 point sinc inter." = OmniConverter 的插值选项名（本地源码确认），
  但 XSynth 渲染器实际映射为 Linear 插值。参考 WAV 由 OmniConverter 的 XSynth 渲染器生成。
- **对齐基准**：xsynth 引擎（本地 xsynth-normal 源码逐行对照）：7 段包络（Lerp/Concave(1-f)^8/
  Convex f^8）、CC7/CC11 平方律 (vol×expr)²（10ms lerp）、pan cos/sin×1.42 clamp、RBJ biquad、
  rubato sinc-32 重采样、渲染到静音（≤0.0001）。
- **GPU 架构**：render.wgsl（每 voice 一线程串行 block，u32+f32 分裂位置计数，
  包络状态机跨 block 持久）+ mix.wgsl（按通道分组求和 + CC 曲线）+ 每块读回状态。
- **懒重采样**：load_soundfont(44100) 不重采样，首次用到时用同款 rubato 重采样到输出率。
- **对齐实验结果**（对 ref 的 corr）：
  - 基线（xsynth 默认设置）：0.974
  - +stereo 双通道上传：0.59→0.974（大修）
  - +use_effects=false（ref 无滤波）：0.982
  - +LinearEnvelope（decay/release 线性，OmniConverter 设置）：0.986
  - 无效：delay 跳过 / release 块对齐 / attack 减半 / sinc_len=8 / CONVEX attack / 无重采样
- **CPU 参考（xsynth-render CLI）不可靠**：第一帧 1e19 尖峰 + 事件时序偏移 4 样本（互相关验证）。

## 依赖关系
- 本 crate：xsynth-soundfonts::sf2（Sf2Region::note_params 烘焙调制器）+ resample + convert_sample_index
- 与 xsynth-normal/core 共享算法（包络/滤波/CC），但不依赖其运行时

## 注意事项
- **剩余 1.36% 差异**（corr 0.986 vs 目标 0.999）：OmniConverter 的 xsynth 版本差异。
  需要用户提供：渲染设置确认（UseEffects/LinearEnvelope/Interpolation）+ xsynth 版本。
- wgpu 27 API 变化：request_device 单参数、PollType::Wait{timeout}、create_compute_pipeline 返回 Pipeline。
- WGSL 保留字坑：active/target/from/out/mix（变量名要避开）。
- naga 不支持 `(expr).method()` 和 `array<f32,N>(0.0)` 构造。
- PowerShell 正则替换易把 `r`n 字面量写进文件（用 edit 工具而非脚本替换）。
